# VLA Verification Framework

First-layer verification pipeline for reasoning Vision-Language-Action models (e.g., pi0.5) using scene graphs as symbolic world models.

## Architecture

Inspired by **SayPlan** (scene graph state transitions with preconditions/effects) and **ConceptGraphs** (VLM-based open-vocabulary scene graphs), the framework verifies whether textual subtasks generated by a reasoning VLA are feasible given the current scene state.

### Package: `vla_verify/`

| Module | Role |
|---|---|
| `openrouter_client.py` | Reusable OpenRouter API client for VLM and LLM queries |
| `scene_graph.py` | Core data structures: `SceneNode`, `SceneEdge`, `SceneGraph` with query/mutation/serialization |
| `scene_graph_constructor.py` | VLM-based initial scene graph construction from image |
| `dsl.py` | DSL actions (`PICK_UP`, `PLACE_ON`, `PLACE_IN`, `OPEN`, `CLOSE`, `RELEASE`) with preconditions and effects |
| `subtask_translator.py` | LLM-based translation of natural language subtasks to DSL actions |
| `verifier.py` | `VLAVerifier` pipeline class tying everything together |

**Entry point:** `run_verification.py` (in parent `py_script/` directory)

No new dependencies required -- uses only `requests` + Python stdlib.

## Design (SayPlan-inspired)

The scene graph is a **symbolic state** where:
- **Nodes** represent entities: objects (movable), assets (fixtures), surfaces, agent (gripper).
- **Edges** encode spatial relations: `on`, `in`, `next_to`, `part_of`, `holding`, `near`.
- Each node carries `attributes`, `state`, and `affordances`.

DSL actions are **state transitions**: each has **preconditions** (checked against the current graph) and **effects** (applied to produce the successor state). For example:

```
PICK_UP(object_id):
  Preconditions: object exists, is movable, gripper empty, object accessible
  Effects: remove spatial edges, add holding edge, update states
```

## Verification Pipeline

1. **Scene Graph Construction** (VLM, one-time): Gemini 2.5 Pro analyzes the scene image and outputs a structured JSON scene graph.
2. **Subtask Translation** (LLM, text-only): Gemini 2.5 Flash translates each natural language subtask into a DSL action grounded in the scene graph.
3. **Verification** (pure code, no LLM): DSL preconditions are checked against the graph state. If valid, effects are applied and the successor graph is returned.

Key design principle: after initial construction, **all verification is purely language-based** (no visual input), reducing hallucination risk.

## Usage

```bash
export OPENROUTER_API_KEY="sk-or-v1-..."
cd py_script/
python run_verification.py
```

### Programmatic usage

```python
from vla_verify.verifier import VLAVerifier

verifier = VLAVerifier(
    vlm_model="google/gemini-2.5-pro",
    llm_model="google/gemini-2.5-flash",
)

# Step 1: construct scene graph from image (VLM call)
scene_graph = verifier.construct_scene_graph("path/to/image.png")
print(scene_graph.summary())

# Step 2: verify a subtask (LLM call + precondition check)
result = verifier.verify_subtask("pick up the black bowl")
print(result.summary())          # ACCEPTED or REJECTED with reasoning
print(result.accepted)            # bool
print(result.scene_graph_after)   # successor state dict (if accepted)
```

## Test Results

Tested with `trial_imgs_0/frame_agentview10.png` and `subtask_samples_0.txt`:

| Category | Count | Result |
|---|---|---|
| Known-false correctly REJECTED | 4/4 | "pick up blue plate", "1No actionput down...", "pick up the sponge", "put down jewelry box" |
| Unlabeled correctly ACCEPTED | 5/6 | "pick up black bowl", "pick up bowl", "pick up the black bowl", etc. |
| **Total accuracy** | **9/10** | |

The one rejected unlabeled entry ("pick up black plate" without extra context) is due to minor LLM inconsistency -- it correctly applied color flexibility for bowls but was stricter for the plate in one instance.

## References

- **SayPlan** (Rana et al., CoRL 2023): Grounding LLMs using 3D scene graphs for scalable robot task planning.
- **ConceptGraphs** (Gu et al., 2023): Open-vocabulary 3D scene graphs for perception and planning.
- **pi0.5** (Physical Intelligence, 2025): Vision-language-action model with open-world generalization.
- **Do What You Say / SEAL** (Wu et al., 2025): Runtime reasoning-action alignment verification for VLAs.
